# data/tracking —— 追踪式计时采集产物（本目录内容不入库）

> 采集器：`scripts/track-collect.mjs`　派生器：`scripts/track-derive.mjs`
> 本目录除 `README.md` 外全部 gitignore（原始帧体量大、且属过程数据）。

## 为什么采这个

手动计时只能覆盖「自己真的坐了」的那几趟；追踪式采集把 DSAT 的实时报站接口当录像看，
盯住每一辆车算「离开 A 站 → 离开 B 站」的时长，用于把「巴士还有 N 站」换算成「还要 X 分钟」。

关键：**站间时长可以按「邻接站对」跨线路共享**，所以采全澳比只采通勤 15 线划算。

## 轮询计划（2026-09-13 全量实测确定）

| 类型 | 条数 | dir 语义 | 每轮请求 |
|---|---|---|---|
| `direction=2`（往返一次返回全程） | 71 | 只查 `dir=0` | 71 |
| `direction=0`（往/返分开返回） | 21 | 查 `dir=0` + `dir=1` | 42 |
| **合计** | **92** | | **113** |

5 秒间隔 → **22.6 次/秒**（对照：DSAT 官网单用户 0.1 次/秒）。
实测吞吐：184 次请求 3.7 秒完成、零失败；单请求 p50 ≈ 15~20ms。

`poll-plan.json` 缓存该计划（含每线每方向的站序，供派生时判「跨站」）。文件缺失时
采集器会按 `direction` 规则现场推导（`--refresh-plan` 可强制重扫并覆盖）。

## 产物命名

```
<stamp>-partNN.jsonl.gz   原始帧，每请求一行；每片都是完整可解压的 gzip
<stamp>-meta.json         本次运行的参数、档位时间线、健康度采样、总计
<stamp>-run.log           人类可读运行日志（中文）
```

`<stamp>` 默认是澳门时间 `YYYYMMDD-HHmmss`，可用 `--label=` 覆盖。

## 原始帧字段（每行一个 JSON）

成功帧：

```json
{
  "seq": 137, "round": 3, "stage": 0,
  "route": "25", "dir": "0",
  "t": 1757767500123, "ms": 18, "ok": true, "hdr": "000", "http": 200, "n": 50,
  "x": { "lastBusType":"2","badCar":"0","lastBusPlate":"AB5479","toBeginBus":"0","busColor":"#276299" },
  "veh": [
    { "idx": 5, "sta": "C653", "main": "C653", "plate": "AB5426",
      "status": "1", "busType": "2", "busCode": "HE244",
      "fac": "0", "flow": "-1", "speed": "4" }
  ]
}
```

失败帧只保留定位信息：

```json
{ "seq": 138, "round": 3, "stage": 0, "route": "26", "dir": "0",
  "t": 1757767500140, "ms": 3001, "ok": false, "err": "timeout" }
```

| 字段 | 含义 |
|---|---|
| `seq` / `round` / `stage` | 全局请求序号 / 轮次 / 当时的渐变档位 |
| `t` / `ms` | **请求发出时刻（epoch ms，UTC）** / 往返毫秒。`t` 是唯一的时间基准 |
| `ok` / `err` | 成功与否 / 失败原因（`timeout` `net:*` `notjson` `token1200` `nopayload`） |
| `hdr` | DSAT 信封状态码（`000` 正常，`1200` = token 失效） |
| `n` | 该次响应返回的站数（与 `poll-plan.json` 的站序长度比对可发现改道） |
| `x` | 线路级附加信息（`badCar` 坏车标记、`toBeginBus` 往总站、`busColor` 公司色） |
| `veh[]` | 该次采样到的每一辆车 |
| `veh[].idx` / `sta` / `main` | 站序下标 / 原始站码（含站台号 `T376/1`）/ 归一主码（`T376`） |
| `veh[].status` | **★ `'1'` = 停靠挂载站；`'0'` = 已离站、驶向下一站** |
| `veh[].speed` | 该车当前速度（km/h）—— 可作「是否真在行驶」的旁证 |
| `veh[].busType` / `busCode` | 车型 / 车辆内部编号（与车牌不同） |
| `veh[].fac` / `flow` | `isFacilities` 无障碍车标记 / `passengerFlow` 客流标记（多为 `-1` 表示无效） |

> ⚠️ 该接口**没有** `stopsAway`（还有几站）字段，也不给经纬度和内部时间戳。
> 「还有几站」是下游自己按站序推出来的。

## 时间口径（本采集的产出必须按此解读）

- 追出来的 `t(离 B) − t(离 A)` = **离开口径** = `run + dwell_B`。
  主人手动打点记的也是「关门起步」时刻，**两者同口径，可直接合并**。
- 现有 `segment_stats` 表按 `src/lib/rebuild/segment-stats.ts` 的注释是**到达口径**
  （`t(到 B) − t(到 A)` = `dwell_A + run`）→ **两口径相差 `dwell_B − dwell_A`，不可直接混用**。
- 原始帧同时含停靠与离站两种状态，**两种口径都能算**，所以口径定案前不需要重采。
- `status` 翻成 `'0'` 由 DSAT 在车辆离站瞬间完成，滞后 ≈ 服务端更新周期(~5s) + 采样间隔(5s)。
- 采样间隔（默认 5s）就是精度台阶：`σ_量化 = S/√12`，5s → ≈1.4s，10s → ≈2.9s。

## 已知缺口（派生阶段处理）

1. **状态缺口**：长驻站后（如总站待发）可能直接翻到下一站的挂载站，**没有 `'0'` 离站帧**
   → 该站的离开时刻不可测，相邻两段被合并成污染值，必须丢弃（宁丢不错）。
2. **跨站**：相邻两次观测的 `idx` 差 > 1 表示中间站没采到 → 该段不是邻接区间，丢弃。
3. **环线/往返**：首尾同码或站码重复时，「沿方向」的相邻关系要按 `idx` 单调递增判定。
