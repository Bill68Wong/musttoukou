# MUST登校 · 需求文档（PRD）

> 版本：v0.3（2026-09-01，优先级重排：数据采集先行；计时器需求细化定稿）
> 状态：已收敛，待作者允许后进入 spec / tasks / checklist 编写

## 1. 项目概述

**MUST登校**——为澳门科技大学学生打造的校园通勤巴士实时报站系统。

- **目标用户**：住在澳科大擎天汇宿舍、每天搭乘巴士往返学校与横琴口岸的通勤学生（首期仅作者本人使用）
- **解决的问题**：现有巴士报站查询繁琐、通勤线路选择多；学生难以精确掌握巴士实时位置与预估到站时间，无法快速选出最快方案
- **项目性质**：长期运营的个人产品（非课程作业），需考虑可维护性与未来开放

### v0.3 新增决策（2026-09-01 需求问答，数据采集先行）

**优先级重排**：数据采集是当前最高优先级，计时器是核心功能；方案选择、实时查询等是后续版本重点。冲刺期定位：专项冲刺 1~2 周（主要方案每条 ≥5 样本）+ 之后长期顺手记；常规采集同时定向补数据缺口（50 路直达横琴验证、T373 步行时间、通关耗时）。

| 决策项 | 结论 |
|---|---|
| 计时引导方式 | **向导式**：系统按所选方案依次提示下一个打点动作，界面突出单一大按钮 |
| 计时前置步骤 | **先选通勤方案再计时**（从已入库 19 方案中选，数据自动归类） |
| 途经站打点 | **能打就打，不作强制**：向导中提供可选打点，漏打不影响流程 |
| 没挤上车 | **一键记录 + 继续等**：保留等待时长并打 missed 标记，自动回到等车状态 |
| 等车实时信息 | **常驻快捷按钮 + 可多次更新**（0/1/2/3/5/8/10+ 站，轻轨为分钟数），形成快照序列 |
| 环境上下文 | **只记拥挤度**（空/正常/挤/爆满），天气不记（可事后反查） |
| 车辆信息 | **系统自动抓取**：等车/上车打点时后台调 DSAT 实时接口存车辆牌号，失败留空 |
| 备注 | **不要**备注字段 |
| 记录修正 | **完全可编辑**（含时间戳），但保留编辑痕迹（原值存档）区分实测与修正 |
| 统计功能 | **极简概览**：每方案样本数 + 总耗时均值/最短/最长 + 采集进度 |
| 数据导出 | **CSV 导出** |
| 数据库架构 | **Supabase 云库为主 + 本地 PG 开发环境 + 每日自动备份回本地** |
| 部署 | Vercel 免费层（已确认），免费子域名（*.vercel.app），做大后再购域名 |
| 访问控制 | **简单口令门**：密码中间件，浏览器记住登录 |
| GitHub | **私有仓库**（含接口逆向成果，不宜公开），Git 操作全部由 AI 代管，用户仅一次性授权 |

### 风险管理维度（2026-09-01 定案，用户要求作为正式项目维度）

| 风控项 | 规则 |
|---|---|
| 第一版 DSAT 接入 | **打点时单次查询**：计时器每次打点（到站/开始等车）后台调一次 DSAT 接口记录当时在线车辆；查询失败留空，不影响计时流程 |
| 后续轮询频率（M3 起） | **仅使用时段轮询，60 秒/次上限**：页面打开才查、页面关闭即停，无人访问零请求 |
| 熔断 | 连续 3 次失败自动停止调用并静默 30 分钟 |
| 每日上限 | 每日请求总量硬性封顶（超限即停，参数可配） |
| 调用日志 | 每次 DSAT 请求成败入库，可查调用量与失败率 |
| 参数管理 | 频率/日限/熔断阈值集中在一个配置文件，改参数不动代码 |
| 行为原则 | 页面标注数据来源「澳门交通事务局」；不对外披露/出售原始数据；对官方服务负担不超过单个用户开网页刷新 |

## 3. 功能需求

### 3.1 MVP（一期，1 个月内）

**F1 最快方案查询**
- 输入：当前时间 + 目的地场景（宿舍/学校/横琴口岸）
- 输出：前 2~3 个方案，按门到门总时长排序，展示：线路、候车预计、乘车预计、步行/换乘/通关耗时、总时长
- 算法：混合兜底估算（实时优先，历史规律兜底）；方案池来自实地走访确认的通勤方案（`data/commute-network.json`）

**F2 实时车辆数据**
- 服务端定时轮询 DSAT 接口（26、50、51、51A、26A、56、25B 等目标线路），缓存入库
- 轻轨班次/间隔数据单独接入（数据源待调研：轻轨官方 App/网站或静态时刻表）
- 前端只查自有后端，不直连 DSAT

**F3 计时器（数据采集）—— 当前版本核心**
- 向导式流程：选方案 → 出发 → 到站/开始等车（自动抓车辆信息）→ [没挤上一键 missed] → 上车 → 沿途各站（可选打点）→ 下车 → 到达 → 结束页勾选拥挤度
- 等车阶段常驻快捷按钮记录「车还有几站 / 轻轨还有几分钟」，可多次更新形成快照
- 记录完全可编辑（保留原值存档）；极简统计概览 + CSV 导出
- 数据入 PostgreSQL，作为预测模型与官方数据缺口的补充

**F4 场景一键首屏**
- 「回宿舍 / 去学校 / 去口岸」三大按钮，点击直达方案页

### 3.2 二期及以后

- 到站/接近提醒（推送通知）
- 开放给其他同学（启用账号体系）
- 更多线路（关闸、氹仔其他常用点）
- 预测模型升级（分时段统计 → ML）

## 4. 非功能需求

- **形态**：PWA，手机浏览器直接使用，可添加到主屏幕
- **性能**：首屏秒开（场景按钮静态化）；方案查询 P95 < 1.5s
- **可用性**：DSAT 接口异常时自动降级为历史估算，界面永不空白
- **可维护性**：DSAT 接口签名/参数集中封装为独立模块，便于随官方变更快速修复
- **合规**：页面标注数据来源「澳门交通事务局」；不对外披露/出售原始数据

## 5. 技术架构

```
┌─ 手机浏览器（PWA）
│    Next.js 前端（场景首屏 / 方案对比 / 计时器录入）
▼
┌─ Vercel（Next.js 服务端）
│    ├─ 方案计算引擎（实时 + 历史混合估算）
│    ├─ DSAT 轮询代理（定时拉取目标线路实时数据 → 入库）
│    └─ 计时器数据 API
▼
Supabase（PostgreSQL 免费层）
     ├─ 实时车辆快照（轮询缓存）
     ├─ 计时器采集数据（打点 + 上下文）
     ├─ 静态线路/站点数据（来自 data.gov.mo + 接口）
     └─ 历史统计（分时段班次规律）

开发期：同一套代码连本地 PostgreSQL（.env 切换连接串，代码零改动）
数据导出：pg_dump 随时可完整导回本地
```

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| DSAT 接口变更/封禁 | 混合兜底估算；接口层集中封装；数据持续自采积累 |
| 1 个月工期紧张 | MVP 只做三场景一线路组，其余延后 |
| 单人数据量不足以建模 | 先用简单分时段均值，随计时器数据积累逐步升级 |
| 通关时间波动大（横琴口岸） | 计时器专项采集通关耗时，按时段建模 |
