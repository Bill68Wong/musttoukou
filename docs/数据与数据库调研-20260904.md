# MUST登校 · 数据与数据库调研报告

> 版本：2026-09-04 · 性质：纯调研汇报（只读核查，未改动任何代码与数据）  
> 数据来源：云端 Supabase（真实主库，只读 SELECT）+ 本地 PostgreSQL 影子库（对照）+ db/ schema 与迁移脚本 + src/ 采集链路代码遍历 + 需求文档对照  
> 核查时点：2026-09-04（云端数据时间范围 09-02 ~ 09-04）

## 0. 结论速览

**一句话定性：采集链路是完整的——数据「采得到、存得下」，当前真正的短板不在采集，而在「真实样本留存太少（云端有效样本仅 5 条）+ 历史规律从未落库（segment_stats 空）」，这两块正是通往「自动选最快线路」必须补上的环节。**

- 云端 Supabase 是**真实主库**：3 天（09-02~09-04）共 108 次计时会话、288 个打点事件、72 条等车快照、316 条车队快照；本地库只是影子库（含 E2E 测试噪声），两者已分叉。
- 采集写入点共 **8 个 API/函数 + 1 个 DSAT 记账旁路**，覆盖「选方案 → 出发 → 到站等车 → 上车 → 乘车逐站 → 下车 → 到达 → 拥挤度」全旅程。
- 单次实测落库 = 1 行 `timer_sessions` + 若干 `timer_events` + 若干 `wait_snapshots` + 一批 `bus_snapshots`，另有若干 `dsat_call_logs` 与每次 DSAT 实查一一对应。
- **最值得注意的现象**：108 次会话中 103 条被软删（用户刻意清理测试/无效记录，数据本身未丢、随时可恢复），统计口径有效样本仅 **5 条**——详见 §1.2 与 §4。
- 本次调研不产生任何 schema/数据改动；优化方向汇总为 §5 backlog，P0 定为 **schema/口径卫生**。

### 1.4 schema.sql 漂移（重要维护隐患）

schema.sql 标注「DROP 后重建」的注释已过期（本体是 `CREATE TABLE IF NOT EXISTS`），且与真实库存在以下不一致：

- `timer_sessions` 缺 `from_zone/to_zone`（v0.4.0 迁移加入，schema.sql 漏并）
- `bus_snapshots` 缺 v0.4.0 归属列（`session_id/stage/ref_station/stops_away`），且该表在真实库中 **session_id 无外键**（本地孤儿快照由此产生）
- `timer_events.event_type` 注释漏 `station_pass`
- `wait_snapshots` 注释「手动 10 表示 10+」与现行 0..11 连续分钟档不符

→ schema.sql 不是可靠单点真相源；重建库需 apply-schema + 依序跑 v040→v071。

## 2. ② 数据采集阶段的数据存在哪

全部 DB 写入集中在 **8 个 API/函数 + 1 个记账旁路**，下面逐一列出「触发时机 / 表与列 / 值来源 / 幂等」。

### W1 · 创建计时会话

- 入口：`POST /api/timer`（首页点方案卡）
- 写：`timer_sessions(plan_id, route_code, dsat_dir, travel_date, weekday, started_at=now())`
- 值来源：方案静态配置 + `deriveRouteDir` 推导方向 + GMT+8 时钟
- 幂等：无（点卡即新会话，设计如此）

### W2 · 打点事件 + 收尾（核心）

- 入口：`POST /api/timer/[id]/events`
- 普通事件 `VALID_EVENTS = depart | wait_start | missed | board | station_arrive | station_pass | alight | border_start | border_end | arrive` → 写 `timer_events(session_id, seq=max+1, event_type, station_code)`
- 副作用：`missed` → `missed_count+1`；`from/to_zone` 合法值 → 更新 `timer_sessions`；`arrive` → 写 `ended_at / time_bucket（am_peak|pm_peak|day|night）/ total_minutes（门到门）`
- 幂等：seq 受 UNIQUE(session_id,seq)；会话已结束则 409 拒写；**无同事件重复提交去重**

### W3 · 出发/到站自动车距

- 入口：`POST /api/timer/[id]/auto-snapshot`（depart/wait_start 后自动，仅巴士段）
- 写：`wait_snapshots(value_kind=stops, value=最近车还有N站, source=auto_depart|auto_wait_start, station_code)`
- 幂等：部分唯一索引 `(session_id, source, station_code)`，同会话同时刻同站仅 1 条

### W4 · 反事实车队快照

- 入口：`POST /api/timer/[id]/fleet-snapshot`（depart/wait_start/alight 后自动，巴士段）
- 写：`bus_snapshots`，对每一条候选线路（最多 6 条）的**每一辆在线车**写一行（route_code/dir/车当前站/plate/bus_code/speed/status/passenger_flow/session_id/stage/ref_station/stops_away）
- 幂等：无，append-only

### W5 · 上车抓车牌

- 入口：`POST /api/dsat/grab`（board 后自动，巴士段）
- 写：① `timer_sessions.vehicle_plate / vehicle_code`（仅当尚未抓过）② `bus_snapshots`（stage=board 一行）
- 选车优先级：停在站上 → 正驶来 → 站上任意 → 全线第一辆兜底

### W6 · 结束页拥挤度

- 入口：`PATCH /api/timer/[id]` → `timer_sessions.crowd_level`（0空/1正常/2挤/3爆满）

### W7 · 软删除（数据卫生手段）

- 入口：`DELETE /api/timer/[id]` → `UPDATE timer_sessions SET deleted_at=now()`；所有统计/导出/列表过滤 `deleted_at IS NULL`
- **软删不丢数据**：events/wait/bus_snapshots 行全部保留，仅统计口径不可见，可随时恢复

### W8 · DSAT 调用记账（旁路）

- `src/lib/risk.ts:logDsatCall`，每次真实 DSAT 请求后写 `dsat_call_logs(purpose, route_code, ok, http_status, error, latency_ms)`
- purpose 实际值：`poll`（eta/auto/fleet）· `timer_grab`（grab）· `sync`（离线同步，仅本地）
- 读取方：仅风控守卫 `guardDsatCall()`（熔断 + 日限 500）

> 注：`GET /api/dsat/eta`（实时车距卡片）只查不落库；`bus_snapshots` 仅由 W4/W5 写入。

## 3. ③ 每次路线实测记录什么、如何入库

向导按方案的 plan_legs 分段生成步骤（walk → depart；bus/lrt → wait_start→board→alight；口岸 → border；末段 walk → arrive）。25 个方案全部以 walk 开头。


### 3.1 分步字段级清单

| 时点 | 用户动作 / 触发           | 写入表与列                                                                             | 值来源                  |
| -- | ------------------- | --------------------------------------------------------------------------------- | -------------------- |
| 0  | 点方案卡                | `timer_sessions`: plan_id/route_code/dsat_dir/travel_date/weekday/started_at      | 方案静态配置 + 方向推导 + 时钟   |
| 1  | 「出发」                | `timer_events(depart, station_code=上车站)`                                          | 用户点按                 |
| 1a | 出发后自动               | `wait_snapshots(stops, source=auto_depart)` 最近车 N 站                               | DSAT force 直查        |
| 1b | 出发后自动               | `bus_snapshots(stage=depart, ref=上车站)` × 候选线 × 在线车                                | DSAT 实时              |
| 2  | 「到站，开始等车」           | `timer_events(wait_start)`                                                        | 用户点按                 |
| 2a | 到站后自动               | `wait_snapshots(stops, source=auto_wait_start)`                                   | DSAT 实时              |
| 2b | 到站后自动               | `bus_snapshots(stage=wait_start)`                                                 | DSAT 实时              |
| 2c | 轻轨「还有几分钟」chip       | `wait_snapshots(minutes, source=manual)` 同站改选覆盖                                   | 用户 chip 0..11        |
| 3  | 「没挤上车」（可多次）         | `timer_events(missed)` + `missed_count+1`                                         | 用户点按                 |
| 4  | 「上车」                | `timer_events(board)`                                                             | 用户点按                 |
| 4a | 上车后自动               | `timer_sessions.vehicle_plate/vehicle_code` + `bus_snapshots(stage=board)`        | DSAT 实时              |
| 5  | 乘车逐站「停靠·记一站」/「甩站没停」 | `timer_events(station_arrive / station_pass, station_code=按次数推算)`                 | 用户按经过站数点按            |
| 6  | 「下车」/动态下车           | `timer_events(alight, station_code=目的地或动态下车站)`                                    | 用户点按                 |
| 6a | 下车后自动（巴士）           | `bus_snapshots(stage=alight, ref=下车站)`                                            | DSAT 实时              |
| 7  | 口岸方案                | `timer_events(border_start)` → `border_end`                                       | 用户点按                 |
| 8  | 「到达」                | `timer_events(arrive)` + `timer_sessions`: ended_at / time_bucket / total_minutes | 服务器时钟 + started_at 差 |
| 9  | 结束页「挤吗」             | `timer_sessions.crowd_level`                                                      | 用户勾选                 |

上下文补充：离校方案 depart 前选「从哪个座」→ `from_zone`；抵校方案 arrive 时选「到了哪个座」→ `to_zone`（均落 `timer_sessions`）。

### 3.2 单次实测「全家桶」行数（巴士单程示例）

- `timer_sessions` **1 行**（含 plan_id/route_code/dsat_dir/日期星期/起止时间/门到门分钟/时段/拥挤度/车牌/分区/软删标记）
- `timer_events` **≥5 行**（depart/wait_start/board/alight/arrive）+ 口岸 2 行 + 逐站每站 1 行
- `wait_snapshots` **2 行自动**（auto_depart + auto_wait_start；多段方案每段 wait_start +1）+ 轻轨手动 minutes 每站 1 行
- `bus_snapshots` depart/wait_start/alight 三时点 × 候选线路 × 在线车数（最多 6 线）+ board 1 行 → 可达几十行
- `dsat_call_logs` 与每次真实 DSAT 请求一一对应

### 3.3 可回推但未单独落库的量

首段步行 = depart→wait_start 事件差；候车 = wait_start→board（含多次 missed 分段）；乘车 = board→alight（逐站事件差可算站间时间）；换乘等待 = 上段 alight→下段 wait_start；通关 = border_start→border_end。这些量**均可由事件时间戳二次推导**，无需额外字段。

## 4. ④ 与当前版本目标（数据收集 → 自动选最快线路）的差距

### 4.1 已具备的能力

- 门到门总时长与各阶段分段耗时：事件时间戳完整可推
- 乘车环境：拥挤度、missed 次数、星期/时段（time_bucket）、学校分座上下文
- 候车实况：出发/到站双时点自动车距 + 轻轨手动间隔
- 真实乘车追踪：19 次会话有逐站停靠记录、11 个车牌、bus_snapshots 反事实车队（同一时刻所有候选线的车在哪）
- 数据链路：全部落到结构化表，软删可恢复

### 4.2 通往「自动选线」的瓶颈

| 缺口           | 现状                                                                        | 影响                                      |
| ------------ | ------------------------------------------------------------------------- | --------------------------------------- |
| **真实样本留存少**  | 108 会话中有效样本仅 5 条（其余为刻意清理的测试/无效记录）                                         | 按(线路,起止段,时段)分组的均值/分布远未达统计量，样本太少时自动选线不可信 |
| **历史规律从未落库** | `segment_stats` 0 行，无写入方也无读取方                                             | 「实时数据 + 历史规律兜底」的 M3 方案缺历史侧数据            |
| **步行实测不回写**  | `walk_times` 始终是 seed 的 10 条 manual 值，计时数据从不回写（depart→wait_start 差可算却未沉淀） | 步行分钟永远是静态估计，不会随实测修正                     |
| **车辆快照只写不读** | `bus_snapshots` 316 条在 src 内零 SELECT                                      | 反事实车队数据尚未被任何分析消费，是未来自动选线最富价值的矿，但现在只是堆积  |
| 轻轨班次表空       | `lrt_schedules` 0 行                                                       | 轻轨只能靠手动分钟，无法自动预估下一班                     |

### 4.3 结论

数据「采得到、存得下」，采集设计已经为自动选线把料备齐（分段耗时可推、车队反事实在库、上下文字段已采）。**当前真正的两个短板：一是真实样本量（需要主人继续日常使用 + 把测试与真实分开，避免误删），二是把已采数据「加工成历史规律」（segment_stats / walk_times 回写）的汇总层尚未实现。** 这些属于后续版本的功能开发，不阻塞当前采集。
