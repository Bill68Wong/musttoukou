## 3. 工作流 A：数据卫生与口径（详细任务）

> 每项均：migrate 幂等脚本（db/migrate-v0XX.ts，云端 `--cloud` + 本地双跑）→ tsc/next build → 只读核对 → git 提交 + 语义化 tag + push。

### A1 真实样本盘点与保护（先行，最高优先）
- 只读盘出当前 5 条真实会话（deleted_at IS NULL），记录 id/线路/日期/时长清单，存入本计划附录；后续所有清理 SQL 一律带 `NOT IN (真实id)` 保护断言。
- 产出：审计基线 SQL（放 .verify/），每次清理前后跑一遍 diff。

### A2 places.school 改名「澳科大」
- DB：`UPDATE places SET name='澳科大' WHERE id=2`（云端+本地）
- 种子源：`data/commute-network.json` places.school.name 同步；`db/seed.ts` 若内嵌同源则同步
- 展示核对：grep 确认无 UI 以 place.name 为文案需补 zone 处；若有，zone 已由 from/to_zone 栏位在 CSV/统计呈现，UI 卡片如需显示「澳科大（N/O 座）」属后续 UI 微调，不在本次
- 文档：`docs/通勤路线与实测数据.md` 基准点描述可保留「N座图书馆大楼」作物理地标说明（不改），但注明 place.name 为泛指
- 验证：云端/本地 SELECT places；首页截图确认无异常

### A3 wait_snapshots manual 全清 + 无站约束
- 清理（先备份 `backups/`，再 migrate 内执行，SQL 带保护断言）：
  - 云端 manual 21 行（id=1、10/11/12、23/24/25、41/43/47/49/53/55/59/61/65/67/71/73/75/80）
  - 本地库同源 manual 行（清点后同规则）
- 加约束防再犯：
  - 部分唯一索引：`(session_id) WHERE source='manual' AND value_kind='minutes' AND station_code IS NULL`（无站时同会话仅 1 条）
  - events API 校验：`type=wait_snapshot & value_kind='minutes'` 必须带 station_code，否则 400
- 保留：轻轨分钟 chip 交互（真实乘坐后使用）；auto_depart/auto_wait_start 自动行不动

### A4 全库测试污染审计（清单化，删改待逐项确认）
- 范围表：timer_sessions / timer_events / wait_snapshots / bus_snapshots / dsat_call_logs / walk_times / commute_plans / stations
- 审计动作（只读）：对每个 session 判定 real/test/可疑——
  - real = deleted_at IS NULL（主人定义：前端未删即真实），目前 5 条
  - test = 软删 + 高事件重复/连点特征 + LRT 密集测试时段（09-03 14:25~16:44 等）
  - 可疑 = 无法判定的列出待主人确认
- 产出：`污染清单表`（会话级：id、线路、日期、事件数、判定、建议处理=保留软删/物理清理/仅标记 is_test），追加到本计划附录或独立 .verify/audit-*.sql + 汇总 md
- 处理原则：软删行统计不可见，**默认不物理删**；仅把测试会话标 is_test=true（配合 A10），真实 5 条 is_test=false 加保护；若主人对某批想彻底物理清理，逐批走备份+清单+确认
- 本地影子库：整体属测试/开发性质，其脏值（'51A/51B' 线路值、孤儿快照、运行中残留）清理方案单列（A6 一并）

### A5 schema.sql 对齐（文件级，不重建库）
- 将迁移已并入的列写回 schema.sql 对应 CREATE TABLE：timer_sessions 补 from_zone/to_zone；bus_snapshots 补 session_id/stage/ref_station/stops_away（标注无 FK 现状与 A6 修复）；timer_events.event_type 注释补 station_pass；wait_snapshots 注释改「手动 0..11 连续分钟档」
- 头部注释修正（不再声称 DROP 重建）
- 产出后 `information_schema` diff 校验 schema.sql 与真实库一致（脚本化放 .verify/）

### A6 bus_snapshots FK / 孤儿清理 / CSV 24 列
- FK：`bus_snapshots.session_id` 加外键（云端无孤儿可直接加；本地先清 279 条孤儿再加，或 FK 用 ON DELETE SET NULL 由迁移清）
- 本地影子库脏数据：'51A/51B' 会话行、4 条运行中残留 → 标记/清理（随 A4 清单）
- CSV 导出第 24 列：`vehicle_code` 纳入（SELECT+header+row 三处小改），列数口径定案 24

### A7 events 接口无站手动分钟 400
- events route 校验前置：拒绝 `value_kind='minutes'` 且无 station_code 的 wait_snapshot（与 A3 约束配套）

### A8 事件幂等（tap_id）
- DB：timer_events 加 `tap_id TEXT`，`UNIQUE(session_id, tap_id)`（多 NULL 不冲突，兼容旧客户端）
- 前端：TimerWizard 每个关键打点（depart/wait_start/missed/board/alight/arrive/station_arrive/pass/border）点击即生成一次 tap_id（如 `${sessionId}-${Date.now()}-${rand}`），重试复用同 id
- API：events route 幂等消费——同 (session_id, tap_id) 已存在则返回已记录（不双写、missed 不重复 +1）
- 验证：.verify/ 双击模拟（并发两次同 tap_id → 只 1 条事件 1 次 missed_count）

### A9 total_minutes depart 起算 + time_bucket 统一
- arrive 收尾改：`total_minutes = now() - (SELECT recorded_at FROM timer_events WHERE session_id=? AND event_type='depart' ORDER BY seq LIMIT 1)`；无 depart 事件回退 started_at
- time_bucket：按 D9 拍板结果（默认：取 depart 事件时刻的时段，与 total 口径配套）写入 arrive 收尾
- 历史已结束会话**不回填**（口径变更只影响未来；文档标注新旧口径分界）
- 影响文件：events route arrive handler；无表结构改动（或按 D9 需加 depart_bucket 时走 migrate）

### A10 is_test 测试标记（列 + UI 开关）
- DB：`timer_sessions.is_test BOOLEAN NOT NULL DEFAULT false`（migrate）
- 回填：deleted_at 非空 → true（测试/无效）；未删 5 条 → false 且加保护（后续清理断言排除）
- UI：计时开始页（点方案卡后/开始前）加「测试模式」小开关（默认关，显眼但可快速切）；测试运行自动写 is_test=true
- 消费：记录列表 / 统计 / 导出默认排除 is_test=true，提供「包含测试」切换（存储偏好）
- 好处：不再需要「跑完手动删」来区分；真实样本自动沉淀

### A11 实际乘车线路记录（补：调研 §4.3 漏项）
- 背景：`timer_sessions.route_code` 取首段 `route_options[0]`；对多候选路段（如去横琴首段可乘 26 或 50），若实际乘非首选项，grab/方向/车队参照会错位到首选项
- 方案（随 A10/Batch2 实施）：board 打点时若该段 `route_options.length > 1`，前端把实际乘车线路一并提交（或 grab 抓到车辆属其它线时服务端更新）；`route_code/dsat_dir` 按实际乘坐线修正
- 影响：TimerWizard board 步骤 UI（多候选时高亮所乘线）、events/board API、migrate 无（应用层字段复用）

## 4. 工作流 B：记录层跨站 fleet 升级（近期，中风险）

> 背景（D4/D5）：未来「自动推荐最快路径」需要回答「坐 50 时，走去蝴蝶谷坐 51A 的总时长是否更短」。车队位置**事后无法回溯**，必须在实测当下把「同一起终点、其它候选方案（含不同上车站）」的车队一并抓下来。门到门建模属分析阶段，但数据现在就要采。

### B1 fleet-snapshot OD 派生改造
- 候选来源改为：查 `commute_plans WHERE from_place/to_place = 本会话 AND is_active` → 每张卡的**首个巴士段**主线路 + 其 `from_station`（上车站）→ 候选集 `[{route_code, ref_station, plan_id}]`
- 抓拍：对每个候选（线,上车站）各取该线「含该站的方向」车辆位置，`bus_snapshots.stops_away = ref_station_idx − bus_idx`（现有列已支持各行独立 ref_station，**无需加表结构**；如后续需要按候选 plan 归类可加 plan_id 列，评估后定）
- 效果示例：坐 50@C653 → 同时抓 26@C653、26A@C653、51@C690/3、51A@C690/1、51B@C690/2（家→校 OD 6 主线的车队各自相对本身上车站）
- 抓拍量：家→校 6 线 / 校→家 4 线 vs 现 3 线，DSAT 调用约 ×1.3~2（当前 360 logs/3 天，风控日限 500 余量充足，仍需 B3 复核）
- 影响：src/lib/dsat/fleet-snapshot.ts、api/[id]/fleet-snapshot/route.ts、会话 GET 若返回 compare_routes 处
- 验证：probe 一次 depart，断言 bus_snapshots 覆盖 OD 全集且各 ref_station 正确

### B2 compare_routes 移除
- B1 上线并稳定后：migrate `DROP COLUMN compare_routes`（commute_plans）+ 种子源 data/commute-network.json 移除该字段 + migrate-v040/060 历史脚本保留不动（幂等已跑）
- 验证：fleet-snapshot 不再读 compare_routes（grep 清零）

### B3 DSAT 风控复核
- 按新抓拍面重算日调用量上界，确认低于日限 500；必要时调整 BATCH_CONCURRENCY
