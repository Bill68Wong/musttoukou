## 3. 实锤缺陷清单

### 🔴 A. 多线混查被静默截断为前 3 条（高影响，最可能的主诉来源）

**位置**：`src/lib/dsat/eta.ts` queryEta 首行 `routes.slice(0, 3)`（注释"最多 3 条 = 最多 3 次 DSAT 请求"，但**调用方未分片**）。

**触发**：方案「去横琴」plan#17 第 4 段在 T355/2 等车，route_options = `[50, 25B, 25BS, 102, 701X, N6]` 共 **6 条**，实际只查询前 3 条（50/25B/25BS）。

**实测证据**（T355/2 六线全停，均能正常查到车）：
- 25B → 停@seq27、102 → 停@seq21、701X → 停@seq20、N6 → 停@seq29
- 全量复现输出：仅 `50=4站 25B=4站 25BS·无车`，**102/701X/N6 三线永久不参与**，若最近的车恰在其中 → 界面报"本方向暂无来车"假阴性，或给出偏大的站数。

**影响面**：计时器 LiveEta 与 depart/wait_start 自动打点（auto-snapshot 传全量 opts，同样被截断 → 采集的站数可能偏高）。

**修复方向**：切片上限放开到 5–6 或对多线分批并发（≤3 条/批，Promise.all），或按"每条线一轮独立请求"重构；同时把截断逻辑上移为显式分片。

### 🟠 B. 循环线"过站绕圈大数"观感误导（中影响，数学正确但难信）

**位置**：eta.ts wrap 分支（`diff<0 → diff+N(+1)`）。

**实测证据**：26 @ T358 单帧 7 辆车中 **4 辆**落在 34~70 站区间（车已过科大站、正在路环/澳门半岛侧绕圈）。这类车真实需绕大半圈才回科大，数学无误，但深夜/清晨车少时若前方无车，界面显示"还有 70 站"，用户无法理解，易判为"系统算错"。

**修复方向**（可选，需拍板）：
1. 保持现状（数字真实）——夜间班次本就稀疏，等待时间确实长；
2. 引入阈值：wrap 距离 > N/2 的车不参与 min，但提示"有 N 辆在远端绕行"；
3. 等车站附近若总站有 pending 待发车，改为优先提示"总站 X 有车待发（发车时间未知）"。

### 🟠 C. 停靠→离站瞬间站数 +1 抖动（中影响，DSAT 口径固有）

**现象**：车停 U-2（status=1）显示"还有 2 站"；离站驶向 U-1（status=0 挂 U-2）变为"还有 3 站"——**车物理上更近，显示却倒退 1 站**，直到进 U-1 才回落为 1 站。已与实测定论口径（N=(U−X)+(s0?1:0)）核对：该口径与 DSAT 官方一致，是"s0=驶向挂载站（挂载站=下一站）"的语义必然，非实现 bug，但刷新瞬间的观感确实像"越等越远"。

**修复方向**（需拍板）：保持口径一致（推荐，官方同款）；或前端对同一车做单调修正（s1→s0 同挂站时数值不增，需额外状态）。

### 🟡 D. 总站待发车信息不足（低影响）

车 status=1 停靠线路首/末总站（如 51A 在 C690/1 或 M93）→ 一律计入 pending"未发车"。用户若恰在总站下一站候车，会看到"未发车"却不知道它几分钟后就来（双方向线起点总站的车其实正待发）。属官方数据边界（无发车时刻表），建议维持现状，仅作展示优化空间。

### 🟡 E. 数据维护脚本风险（低影响，运维提醒）

`db/sync-routes.ts` 第 50 行 `DELETE FROM route_stations` **无 kind 条件**——v071 补的 34 行 LRT 站序会在下次全量重同步时被清掉。建议 DELETE 加 `WHERE route_id IN (SELECT id FROM routes WHERE kind='bus')`。

4. **算法基准维持**：DSAT 官方口径（2026-09-03 实测定论 N=(U−X)+(s0?1:0)）不变。
