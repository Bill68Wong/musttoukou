## 三、★★ 事故复盘

### 3.1 触发链（逐行日志）

```
[04:09:34]    ✗ 3A/d0 timeout
[04:09:34]    ✗ 6A/d0 timeout
[04:09:34]    ✗ 6B/d0 timeout
[04:11:34]    ✗ 3/d0  timeout
[04:11:34]    ✗ 3/d1  timeout
[04:11:34]    ✗ 3X/d0 timeout
[04:11:35] 🔻 降档 档2 → 档1（窗失败率 6.0%）
```

- **同一秒内 3 个不同目标同时超时** → 旧滑动窗口（**最近 50 个请求**）失败率 = `3/50 = 6.0% > 5%` → 降档
- ⚠️ **时机极不巧**：降档发生在第 **10.5 分钟**，而渐变期满（`--ramp=3,3,5` = 11 分钟）**只剩 25 秒**
  —— 再等 25 秒就会进入档3 全速
- 全轮共 11 次失败，但日志只打印每轮前 3 条（`if (failN <= 3)`），故 `✗` 行仅 8 条；
  另一个成簇点 `04:09:34`（`3A`/`6A`/`6B` d0）本来也接近触发阈值

### 3.2 根因判定：**本机瞬时停顿，不是服务端**

| 判据 | 实测读数 | 若为服务端应看到 |
|---|---|---|
| 服务端延迟 | p50 全程 **13~17ms**，四档基线 14/14/14/15ms **纹丝不动** | 拥塞 → p50 必同步抬升 |
| 失败性质 | 全为 **`timeout`（3000ms）** | 连接被拒 / 应答超时同样可能，但会伴随 p50 抬升 |
| 连接层失败 | **零 `net:fetch failed`** | 被拦截 / 隧道断会出现 |
| 失败形态 | **同一秒 3 个目标一起超时**（簇状） | 服务端压力是渐进的，不会挑同一秒 |
| 目标分布 | `3/d0`、`3/d1`（**同线双向**）、`3X/d0` | —— |

**机理**：`pool=6` + `timeout=3000ms` → 本机一次约 3 秒的停顿，会同时打断多个在途请求，
表现为「同一秒多个目标一起超时」。若是服务端慢，6 个并发请求不会整齐地在同一秒失败。

### 3.3 暴露的三个护栏缺陷（均已在 v0.27.4 修复）

| # | 缺陷 | 代码位置 | 后果 |
|---|---|---|---|
| ① | **降档单向不可逆** | `if (!degraded && curStage < 3)` —— `degraded` 一次置 `true` 即**永久锁死**，档位轮转与升档逻辑整体停摆 | 瞬态 6% 把整轮钉在低档 19.5 分钟 |
| ② | **窗口按「请求数」而非「时间」→ 高档位极敏感** | `health.win` = 最近 **50 个请求**；档3 时 50 请求只相当于 **0.44 轮** | 一轮里 3 个失败即触发降档 |
| ③ | **无「同秒突发 = 客户端侧」豁免** | 无此判据 | 一眼可辨的客户端事件被照单全收 |

### ★ 关键结论

1. **档位只改「覆盖线路数」，完全不改「对已覆盖线路的采样频率」**
   —— `slot = intervalMs / reqs.length`，档1（33 请求/5s）与档3（113 请求/5s）对每条线**都是每 5 秒 1 次**。
   实测证实：**A 组每方向 324~360 帧 / 26.9~29.9 分 = 12 帧/分 = 5 秒**，与跑满档3 时**完全等价**。

2. **实际损失 = 后 44 条线（92 − 48）**，而不是先前估计的 68 条。
   因为档2 阶段（4.4 分钟）已经覆盖到前 48 条 → **B 组 24 条虽只有 4.4 分钟，但同样是 5 秒密度**，
   仍然可用（样本量约 53/方向，对「同键 n≥5」的护栏判据已经够用）。
3. ⚠️ **对本轮定位的修正**：此前口头报告说「只覆盖 24 条线」，**实测应为 48 条**。
4. → **结论：不要因为降档就丢弃该轮**。A 组可用性 100%，B 组可用性受限于时长（4.4 分钟）而非密度。

## 七、教训与建议

1. ★★ **「护栏误判」和「服务端异常」必须用 p50 区分**：服务端拥塞必然抬 p50；p50 纹丝不动而失败成簇

2. ★★ **降档不等于整轮报废**：档位**只改覆盖线路数，不改采样频率** → 降档轮里被覆盖线路的数据
   与全速轮**等价**。实测本轮 48 条线全部 5 秒密度。→ 以后遇到降档先看覆盖度再决定是否重跑。
3. ✅ **护栏四修已上线（v0.27.4）**，并配 `--selftest` 离线自检；**改采集器后先跑自检**。
