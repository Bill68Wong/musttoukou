## 0. 先说一个必须先讲清的口径问题（很重要）

用户要追踪的是「**离开 A 站 → 离开 B 站**」，但现有 `segment_stats` 存的是
「**到达 A 站 → 到达 B 站**」（见 `src/lib/rebuild/segment-stats.ts` 头注：
段时长 = `t(下一站) − t(上一站)`，端点只认 arrive/pass/board/alight）。

**两者不是同一个量**。展开：

```
到达-到达：  arrive(A) → arrive(B)  =  dwell_A + run_{A→B}
离开-离开：  depart(A) → depart(B)  =  run_{A→B} + dwell_B

相减 = (arrive(B)−arrive(A)) + dwell_B − dwell_A
```

→ **只有在「A 站停站时长 = B 站停站时长」时，两者才相等。**

这**正好是用户那个「抵消」直觉的第二次出现**：不仅两次检测延迟可能抵消，
两次停站时长也可能抵消。但同样是随机量，也同样是「均值抵消、方差放大」。

**所以实验必须同时记录两种口径**，否则拿「离开-离开」去比「到达-到达」，
差出来的是 `dwell_B − dwell_A`，会误判成「追踪算法不准」。

### 本项目停站时长有多大？（实测）

- `segment_stats` 的 `stop`（含起点停站）vs `pass`（起点甩站≈纯行驶）之差 = 停站耗时
- 本次 25 路实测：`AB5479` 在 T363/2 **连挂 45 秒不变**；`AB5413` 在 C654/3 停 **35 秒**
- → **停站时长 0~45 秒+ 波动**，不可忽略

## 2. 实验设计

### 2.1 选段原则
挑一段**你常坐、且目前样本最成熟**的：
- **首选 `T375 → T380`（26 路，n=3，avg 1.4 分）** —— 这是 26 路的核心段，11 条线共享
- 备选 `C653 → C692`（25 路，n=3，avg 2.1 分）—— 擎天匯一侧

### 2.2 采集方法（追踪侧）
对目标线路持续轮询（建议 **10 秒**，与官网同频），对**每一辆在线车**记录逐帧：
```
{ 帧时刻, 车牌, status, 挂载站 mainCode, idx }
```
存为 JSONL，事后再跑状态机（**不边采边判**，判错无法回溯）。

### 2.3 状态机（同时产出两种口径）
```
对车牌 P 逐帧扫描：
  A. 到达口径（对齐现有 segment_stats）
     arrive_ts(B) − arrive_ts(A)      ← 「车停稳在 A」到「车停稳在 B」
  B. 离开口径（用户要的口径）
     depart_ts(B) − depart_ts(A)      ← 「车离开 A」到「车离开 B」
  事件定义：
     arrive_ts(X) = 首次出现 (status='1' 且 挂载站=X) 的帧时刻
     depart_ts(X) = 首次出现 (status='0' 且 挂载站=X) 的帧时刻（且此前见过 s1@X）
```
→ **两种口径都算**，与现有 `segment_stats` 的 `avg_minutes` 对比，看差多少。

### 2.4 对照方法
| 对照项 | 追踪式 | 现有真值 | 差值含义 |
|---|---|---|---|
| 到达-到达 | `arrive(B) − arrive(A)` | `segment_stats.avg_minutes`（stop 档） | 应接近；差 = 追踪误差 |
| 离开-离开 | `depart(B) − depart(A)` | 上值 + `dwell_B − dwell_A` | 差 = 停站差 + 追踪误差 |
| 停站时长 | `depart(X) − arrive(X)` | 无现成真值（需 `stop` vs `pass` 反推） | 可交叉验证 |

### 2.5 样本量目标
- 单段追踪 **≥5 辆车** 的完整「停在 A → 离 A → 停在 B → 离 B」序列
- 按 26 路实测（每辆车间隔约 5~10 分钟），预计 **需挂机 30~60 分钟**
- 建议跑 **1~2 个时段**（如早高峰 + 平峰），看误差是否随时段变化

## 3. 实验能回答什么

| 问题 | 能否回答 | 判据 |
|---|---|---|
| 两次延迟是否抵消？ | ✅ | 算「到达-到达」与真值的偏差分布，若均值≈0 → 系统偏差确实抵消；若标准差大 → 抖动没抵掉 |
| 追踪式与实测差多少？ | ✅ | 同一段「到达-到达」追踪值 vs `segment_stats` 实测值，逐车比 |
| 「离开-离开」能否用？ | ✅ | 与「到达-到达」之差 = 停站差，看是否稳定 |
| 10 秒 vs 5 秒 差多少？ | ⚠️ 可选 | 同一时段跑两种间隔，比较 |
| 甩站怎么处理？ | ✅ | 若 idx 跳 >1 则标记为「甩站段」，单独统计 |

## 4. 已知风险 / 局限（先讲清楚）

1. **真值本身也是「近似」**：`segment_stats` 的 n=3~4 也是小样本，本身有误差。
   → 只能看「差异的量级」，不能当精密校准。
2. **口径不同**：如第 0 节所述，必须同时算两种口径，否则会误判。
3. **时段/拥堵影响**：真值是多时段混合的平均值，追踪是某一时刻的瞬时值，
   → 单次对比必然有差，要看**分布**而非**单点**。
4. **轻轨不可做**：无逐车实时位置（见 1 节脚注）。
5. **需要你在场对照（可选但更好）**：若你愿意在追踪时**同时手动计一次**，
   就有「三方对照」（你手动 / 追踪 / 历史统计），说服力最强。
