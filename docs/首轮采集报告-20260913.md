## 三、★★ 根因：派生器压缩键漏 `idx`（第一版假设被数据推翻）

### 3.1 现象

`npm run track:derive -- --label=20260913-213049 --truth=cloud` 出：
双口径差 **σ 75.7 秒**（此前小样本测的是 20.6 秒）、绝对差最大 **960 秒（16 分钟）**，
且与真值对照出现 `51路 C688→C690：追踪 12.83 分 vs 真值 1.48 分`。

### 3.2 两个被否掉的假设（避免以后重走弯路）

| 假设 | 否定证据 |
|---|---|
| 多辆实体车共用同一 `plate` 串（中转/加车）→ 时间线交错 | 轮询计划里 `platesSharedAcrossDirs = **0**`（92 条线全无跨方向共用牌照）；轨迹压缩后**无交错**，且异常段「状态缺口」为 0 |
| 终点站掉头导致 `depart` 配对错位 | 把 `idx` 纳入压缩键后，「离开该站时 idx 变了」的标记**命中 0 条** → 不是掉头 |

### 3.3 真根因

`src`…准确地说是 `scripts/track-derive.mjs` 的 `extractEvents()`，压缩连续同状态时**键只有 `(status, main)`**：

```js
// ❌ 旧：漏了 idx
if (last && last.status === s.status && last.main === s.main) { last.lastT = s.t; last.n++; }
```

而车辆在某站驻留期间，**`idx` 会静默重锚**（终点掉头换方向、或 API 重新定位车辆）——
出现「同 `main`、同 `status`、但 `idx` 已变」的连续帧。只按 `(status, main)` 合并 →
重锚前后的帧被并成**同一组**，而组的 `idx` 停在**首帧值** → 之后生成 `depart` 事件时带上**过期 idx** →
`b.idx − a.idx === 1` 的「严格相邻」过滤**看着正常却被骗过** → 造出一段横跨真实驻留期的**假区间**。

辨识度极高的轨迹形状：

```
s1@M285  idx=25  21:42:29~21:42:59   ← 正常到站
s0@M285  idx=25  21:43:09~21:43:39   ← 正常离站（真区间开始）
s1@M18   idx=26  21:43:49~22:00:19   ← 到终点站，驻留 16.5 分钟（其间 idx 静默变成 0）
s0@M18   idx=**0** 22:00:29~22:00:49  ← 以 idx=0 离站（返回方向）
        → 旧代码把「离 M18」的 idx 记成 26 → 与上一站 25 相邻 → 生成 17.33 分的假区间
```

### 3.4 修法（两处，缺一不可）

1. **压缩键加 `idx`**：`last.status===x.status && last.main===x.main && String(last.idx)===String(x.idx)`
2. **加护栏**：只接受 `s0 帧的 idx === s1 帧的 idx` 的 `depart`，否则该站离开时刻不可信

### 3.5 修复效果（只读复算，未改动仓库代码）

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 「离开口径」最大样本 | 22.50 分 | **10.99 分**（= 真实跨海段） |
| 双口径差 σ | 75.7 秒 | **33.0 秒** |
| 双口径差 均值 | — | **−1.4 秒**（≈0，无系统偏差） |
| 双口径差 最大绝对值 | 960 秒 | 370 秒 |

→ **结论：原始帧是干净的，问题全在解析层。不需要重采。**

### ★ 补充证据：「−18 秒系统性偏差」100% 来自时段错配，不是口径误差

报告初版看到「平均符号差 −18 秒 → 存在系统性偏差」时，我做了归因核查
（`.verify/truth-bucket.mjs`）：把**真值也按时段 / 类型同口径化**再比：

| 真值过滤方式 | 可对照段 | 平均绝对差 | 平均符号差 | ≤0.5 分 |
|---|---|---|---|---|
| 全时段全部类型（初版做法） | 227 | 34 秒 | **−18 秒** | 127/227 |
| 只取同时段（night） | 76 | 26 秒 | **−4 秒** | 56/76 |
| **同时段 + stop 型** | 56 | **17 秒** | **−0 秒** | **46/56（82%）** |
| stop 型（全时段） | 204 | 34 秒 | −19 秒 | 113/204 |

**结论**：

- 只要**同口径化**（同时段 + 同事件类型），偏差**归零（−0 秒）**，平均绝对差降到 **17 秒**，
  82% 的段落在 ±30 秒内 → **口径选择没有错，离开口径就是对的**。
- 「−18 秒」是**时段错配**造成的假象：本轮只在夜间（21:30–22:00，路况顺畅）采，
  而真值是**全时段加权平均**（含早晚高峰）。
- ⚠️ **这条对建模是硬约束**：夜间样本的站间时长比全天平均**短约 20%**
  （−18 秒 / p50 约 90 秒）。**拿夜间数据去预测早高峰会系统性低估**，
  叠加 N 段后误差会放大 → **必须补齐 am_peak / day / pm_peak 三个时段**，不能只用一轮数据建模。
