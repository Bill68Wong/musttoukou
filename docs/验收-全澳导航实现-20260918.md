## 验收结论（TL;DR）

- **总体判断：需修复后上线** —— **导航主链路（搜索→出发→出卡）可用且质量不错，但「卡片 → 详情页」这一步在真实用户流程下必崩**（P0）。修掉 P0 后即可上线。
- **P0（阻塞上线）1 个 · P1（上线前应修）4 个 · P2（可迭代）5 个**
- **最致命的一条**：点任意一张卡进 `/nav/detail` → **服务端异常（应用错误页）**。根因是 Server Component 把**函数** `colorOf` 当 prop 传给 Client Component `RouteStack`（RSC 不能序列化函数）——`next build` 通过、`tsc` 0 错误、`GET /nav/detail` 也返回 200，**但真实浏览器点卡即错**（决定性复现见 §①/§④）。

> 先说好的（都在主链路）：**两段式搜索**（打字纯本地 0 配额 / 回车走高德）按 R5 落地并带「来自高德」徽章 ✓；**车程走 `lookupHop` 逐跳实测**（抽查 25 路 5 跳全 L1 实测）✓；**步行 = 高德几何 ÷84**（278m→3.3 分）✓；**卡片数按实际显示**（home→school=3 张、school→gate=2 张，不凑 5）✓；**middleware 白名单已正确加**（公众可访问）✓；**旧功能未破** ✓；首页 0 console error ✓。

### ② 阴影对照扩样（≥30 OD · 漏线率真实数字）

- **扩到 32 OD**（锚点：home/school/gate/hengqin/T317(氹仔码头)/M134(市中心)/T322/LRT-MUST/C690；含校园走廊/口岸/氹仔/跨区）。**凌晨 01:29**，1 个 OD（school→LRT-MUST）高德 0 方案已跳过并标注「深夜样本不足」。
- **真实漏线率（Σmiss÷Σ高德组合）**：

| 配置 | 漏线率 | 本地路径合计 | 触顶 |
|---|---:|---:|---|
| A `k=8, cap=80`（= engineer 同口径） | **72.9%** | 2480 | **32/32 全触顶** |
| B `k=8, cap=2000` | **53.5%** | 62000 | 全触顶 |
| C `k=16, cap=2000` | **34.1%** | 62000 | 全触顶 |
| D `k=40, radius=3km`（近似含高德站） | **26.4%** | 155000 | 全触顶 |

- **口径复核结论（独立）**：
  1. **engineer 的 58.3% 是真实计算，但样本偏小且被上限放大**：其脚本 `shadow-diff.ts` 里 `searchStationPaths(..., {maxCandidates: 80})` 是**硬编码**，而实测 **每个 OD 都触顶 80** ⇒ 枚举在「0 换乘」或「1 换乘」中途被截断，大量合法组合从未生成。
  2. **仅把 cap 从 80 抬到 2000**，漏线率从 **72.9%→53.5%（−19pp）** ⇒ 该数字**约六成是 cap 假象**。engineer 的根因分析（「高德选的 C653 是第 9 近站 ⇒ 被 K=8 截掉」）**部分成立但不完整**——cap 同样是主因。
  3. **评估缓解方案「把高德选中的上下车站并入本地候选」**：用配置 D（k=40/3km，足以覆盖高德选中的站）近似 ⇒ 仍 **26.4% > 10%**。**⇒ 该缓解不足以把漏线率压到 10% 以下**；残余来自 ① 链中含 `__amap_`（站码映射失败，永不匹配）② 本地有界 BFS 的 hub 限量（25）与「中段=两 hub 共有线」约束。
- **重要边界**：**主路径交付的是高德方案本身（漏线=0）**，此指标只反映 **降级引擎完整性 + 监控信号**。故 P1-1 的实际影响是「降级质量 + 监控阈值不可用」，而非主路径缺路线。

### ③ 2 个残留 miss 的复核结论

**结论：不是脚本/映射 bug，是真实「高德路径 vs 用户实际捷径」的口径差（且样本极小）。**

| 例 | 直线 | 高德 | ratio | 实测 | 折算(高德÷84) | 隐含速度 | 判读 |
|---|---:|---:|---:|---:|---:|---:|---|
| home→C653 | 228.0m | 309m | 1.36 | 2.8 分 (n=13) | 3.7 分 (+31%) | 1.84 m/s(高德) / 1.36(直线) | 高德 ratio **正常**（∈[1,3]→按规则保留），但路径比人走的捷径长 ⇒ 规则无法识别 |
| school→T400 | 474.3m | 716m | 1.51 | 6.5 分 (n=**1**) | 8.5 分 (+31%) | 1.84 / 1.22 | 同上；且实测样本仅 1，噪声大 |

- 两例 ratio 都落在「正常区间」，**任何规则都不该改**（改了会犯 ×1.5 误伤 38% 的旧错）⇒ 属**固有残差**。
- 附带发现（供校准口径修正）：全表 44 行「折算 vs 实测」中位 ratio **0.90**，`±20%` 命中仅 **21/44**；但该统计**未按 zone 对齐**（把 R 座实测 2.8 分错配到 966m），故偏低是假象；`calibrate-walk.ts` 的 zone-aware **90.0%（18/20）** 更可信。
- **裁定**：engineer 的「属高德路网 vs 实测口径差」判断**正确**，接受为已知残差；建议把两例写入「非 bug 清单」。
